DVWA lab: Reflected XSS, low security level

Lab: DVWA, intentionally vulnerable, local install only. Tool: Firefox and Caido proxy.

What I tested

I entered a name in the reflected XSS form and checked if my input was shown back in the page without safe encoding.

What happened

At low level, the input was reflected in the response. That means attacker controlled text could change how the page behaves for a victim who clicks a crafted link.

Why it matters

Reflected XSS can be used for session theft, fake login pages, and redirects. It needs a victim to click, so it is often paired with phishing, like the email in my other article.

The fix

Encode user input on output with a function like htmlspecialchars in PHP, validate input on the server, and set a strong Content Security Policy. Never trust browser JavaScript checks alone, because a proxy like Caido can bypass them.

What I learned

Client side checks are for user experience, not security. The real check must happen on the server.
